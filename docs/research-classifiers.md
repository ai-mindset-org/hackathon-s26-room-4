# Товарные классификаторы для еды — что есть и чего нет

Разведка 29.08.2026. Проверено скачиванием файлов, не по статьям.

## Главный вывод

**Готового справочника, который доводит до «филе грудки цыплёнка-бройлера
охлаждённое» или «Говядина Рибай», не существует нигде.** Ни ОКПД2, ни ТН ВЭД,
ни GS1 GPC, ни UNSPSC. Все официальные системы останавливаются на уровне
**вид животного + термическое состояние**. Дальше — отруб, сорт, степень
обработки — это всегда собственный слой, который каждая компания строит сама.

Доказано руками: скачан текущий ОКПД2 (`classifikators.ru`, 703 КБ xlsx),
прогреплены 38 830 строк.

```
говядина  → максимум «Говядина замороженная» / «охлаждённая». Отрубов нет.
курица    → «Мясо кур, в т.ч. цыплят (включая цыплят-бройлеров) охлаждённое».
             Частей тушки нет.
филе      → есть ТОЛЬКО для рыбы (25 строк: филе рыбное свежее / охлаждённое /
             мороженое, пресноводной / морской).
```

То есть наши ложные привязки — не баг матчера. Это попытка получить от
классификатора точность, которой в природе официальных классификаторов
для мяса просто нет.

## Что где лежит

| Классификатор | Глубина по мясу и птице | Где взять | Проверено |
|---|---|---|---|
| **ОКПД2** | вид + термосостояние, без отрубов | `classifikators.ru/okpd` → xlsx 703 КБ | ДА, скачан и прогреплен |
| **ТН ВЭД ЕАЭС** | до частей тушки птицы (0207 13/14), говядина только обвал./необвал. | `eec.eaeunion.org`, официальный текст PDF/Word | частично: текст открыт, bulk-файла нет |
| **GS1 GPC** | Brick «Poultry» + атрибут «Cut Type» — отруб как АТРИБУТ, не код | `gpc-browser.gs1.org` → full package zip | частично: страница открыта |
| **UNSPSC** | уровень живого скота и кормов, пищевой детализации почти нет | `unspsc.org`, бесплатно | непроверено |
| **CN / Prodcom** (ЕС) | тот же HS-ствол, Prodcom грубее | `data.europa.eu`, CSV/RDF | ДА, распределения открыты |
| **Open Food Facts** | ДОХОДИТ до «Chicken breast without skin raw» | `raw.githubusercontent.com/openfoodfacts/openfoodfacts-server/main/taxonomies/food/categories.txt` | ДА, скачано 3.6 МБ, 126 405 строк |
| **ФГИС Меркурий / ВетИС** | иерархия + коды ТН ВЭД + категория (сырьё/полуфабрикат/готовое) | `help.vetrf.ru`, WSDL/SOAP | схема открыта, доступ к API — по сертификату участника |

⚠ Open Food Facts доходит до нужной глубины, но это про **продукт с этикетки**,
а не про B2B-товар от поставщика. Для розницы годится, для опта — нет.

## Как это устроено в проде

Одна и та же форма у всех, кто решал задачу всерьёз:

- **Instacart** — таксономия остаётся грубым скелетом («Dairy > Cheese >
  Parmesan»), а точное сходство держат отдельно на эмбеддингах. Расхождение
  кода с меткой таксономии само стало сигналом ошибки в таксономии.
- **Shopify Catalog** — детерминированные правила (общий бренд, модель, тег)
  сначала, LLM только на неоднозначный хвост. Кластер = бренд + модель, а не
  единый глобальный код.
- **Uber Eats INCA, Claro** — дешёвый детерминированный слой резолвит
  большинство, вероятностный слой только на серую зону, и обязательно порог
  уверенности плюс проверка человеком. Не единый решающий балл.

## Что из этого следует для нас

1. **Транк — официальный код.** Вид животного плюс термическое состояние
   берутся из ОКПД2 (или ТН ВЭД, если пойдёт импорт). Это единственное, что
   даёт устойчивый внешний код.
2. **Отруб — отдельный атрибут поверх кода**, по образцу GS1 GPC
   Brick + Attribute. Не пытаться впихнуть его в один общий балл вместе с видом
   животного — именно это рождает ложные привязки.
3. **Вид животного — блокирующий признак, а не весовой.** Разный вид → ноль
   сразу, без взвешивания. «Цыплята отборные» никогда не должны были
   подтянуть «Яйца куриные»: у них разный транк.
4. Внутри одной пары «код + отруб» — детерминированный слой на явном,
   человек на сером хвосте. Это ровно то, что у нас уже сделано очередью
   гейтов.
